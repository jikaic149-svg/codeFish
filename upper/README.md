本目录复用只读来源 `C:/Users/rlyoulo/Desktop/robofish_new/upper` 的顶层工作站源码，保留原作者信息。没有复制原工程的数据、模型 DLL、画像素材、EmberProbe 或固件工具。原目录未修改。

双击 `start.cmd`，或在本目录运行 `python -B launch.py`，打开 `http://127.0.0.1:8766/`。新服务身份为 `robotfish-local`，独立于旧工作站的 8765；不会结束其他目录或其他程序的进程。可用 `ROBOFISH_HOST_PORT` 同时调整启动器与服务端口。

本版源码服务修订为 `workstation-36-steering-priority`，当前配套固件为 `2.7.7-steering-priority`，包含实测推进前馈所需的尾攻角循迹分配；旧固件需升级后再启动新循迹。连接 LoRa 串口后可独立手动控制，无需 Wi-Fi；连接机器鱼 Wi-Fi 后自动识别地址并建立控制连接。同目录旧版后台占用端口时，启动器核对服务身份和目录，结束旧版后启动新版；同版本则复用，不重复启动。仅刷新浏览器不能更新已运行的 Python 后台；重新打开启动器可以载入新版本，电脑网络无需切换。本次未自动烧录固件或发送实鱼目标。

视觉页默认加载视图和观测，保留预览与手动航向实验；完成实时相机场地／鱼头标定并画好路径后，点击“开始自动循迹 · Wi-Fi”才发送运动目标。PC计算LOS航向与视觉速度闭环，S3负责本地yaw PID。启动自动循迹会全停、关闭本机LoRa发送端、连接Wi-Fi控制并等待原3秒LoRa健康窗口释放；之后最高10Hz提交最新目标，100ms周期包含HTTP耗时，不积压补发。当前默认速度0.12m/s、前视50／35cm、横向增益0.6；速度PID为60／10／6，配置集中在 `vision/configs/control.json`，没有恢复速度输入上限。控制使用最新有效IMU，视觉测量仍按图像时刻配对。录像回放只允许观测。调试终端跨页面持续收集PC与鱼端回传，显示成功目标数量及退出原因；完整参数和日志依据见[循迹说明](../docs/guides/vision-control.md)。

终端改为增量追加行；1000行约1MB隔离夹具的刷新中位耗时从30.4ms降至0.4ms，只代表终端刷新。主面板合并为最高5Hz渲染，遥测和控制频率保持；开发／网络功能按页面和活动任务轮询，详细JSON只在展开时刷新。网页隐藏时关闭视频显示，不停止后台视觉和自动循迹。本组循迹参数未做新的实鱼验证。

操控页常驻显示“LoRa 已连接／未连接／串口异常”和独立的 Wi-Fi 遥测状态。点击“连接设置”，最上方 LoRa 面板会扫描电脑串口，下拉列表显示端口编号和设备名称，由用户选择 LoRa 适配器后点击连接；没有默认端口，不会猜选第一个设备。插拔后点击“刷新串口”，仍存在的选择予以保留，已消失的选择清空；没有设备时提示接入 USB 转 TTL。扫描与选择都不打开串口，只有点击连接才打开用户所选设备；后端连接前再检查实际存在性，缺少端口或已拔出时直接提示重新选择，不回退到其他编号。参数仍为115200 / 8N1、鱼端地址 0x0102、信道 0x20，沿用当前鱼端 v2 CRC 协议。不要求先发现鱼、填写 IP、完成 Wi-Fi 登录或收到遥测，即可选择运动模式、按键／按钮操控及全停。Wi-Fi 中断不会清掉有效的 LoRa 按键；串口异常才清除旧输入，需人工重连并重新按键。断开／重新配置串口和退出后台前提交一次 STOP，重新连接只发心跳，不恢复旧目标。

LoRa 状态明确显示“发送端已打开／发送端未连接／发送端断线”；生产链路没有新增 LoRa 应答。Wi-Fi 有效时按鱼端遥测显示近期收包状态，没有 Wi-Fi 时显示“鱼端状态未知”，IMU、执行器、安全状态继续留空／未知。发送统计独立从本机 `/api/station/lora` 读取；串口写入成功不代表鱼体已执行。Wi-Fi 断线后设备徽标同步显示断线，不再用缓存身份显示在线。

连接 LoRa 后默认选择自动主备：LoRa 优先；鱼端报告 LoRa 超过原有 3 秒健康窗口且 Wi-Fi 遥测／控制会话可用时，后续新操作通过 Wi-Fi 备用。恢复 LoRa 时保留原有中立接管屏障，不重放旧目标。也保留显式“仅 LoRa”选项，供用户主动选择；该选项下 Wi-Fi 仅读遥测。此默认行为按本次要求恢复，覆盖上一轮默认仅 LoRa 的选择。3 秒为主链路健康判断，不是指令无变化就停机的运动租约。

发送线程按提交事件唤醒，普通帧最小间隔由500ms降为250ms；持续提交相同目标时仍合并为每秒一次续发，待发运动目标只保留最新值，STOP立即唤醒并优先提交。没有新的用户输入时不会自动重发运动目标。LoRa 可用时，Wi-Fi 登录／自动连接不占用遥控请求队列；控制配置提交后也不再等待慢速遥测才解锁按钮。250ms是本机提交节奏，不是空口或鱼端执行时延的实测保证。

外部摄像头自动检测0～9号可读取画面的输入，下拉列表显示实际索引和检测尺寸，支持插拔后重新检测。检测在独立进程执行且有超时；运行视觉时先停止再检测。实时采集请求MJPEG及30fps，保留相机默认尺寸，避免强制1280×720后回落到慢速未压缩格式；设备不支持的设置可能不生效。分辨率改变时原有逻辑要求重新标定。RobotFish机型只禁用板载相机选项，外部视觉的“开启画面”按钮正常可用。

数据页新增“LoRa 发送端耗时”，即使没有 Wi-Fi，也显示最近一次目标变化／设置的本机排队、USB串口写入和合计时间；不包含浏览器输入、空口传输或鱼端执行。相同目标的保持续发不覆盖最近操作的计时。后台 `lora_uart_tx` 日志另记每个控制帧的序号、字节数、排队／写入耗时和是否续发。串口写入完成不等于无线发送完成或鱼端收到。

右上角“退出上位机”会结束本机后台并释放端口；关闭浏览器标签只关闭页面。退出前会确认未导出的实验记录，向本机已持有的控制会话提交一次全停，再关闭 LoRa 串口；实际全停未确认时在退出页明确提示。没有打开页面时，可双击 `stop.cmd`，或运行 `python -B launch.py --stop`；`start.cmd --restart` 可重启。新版使用受本机 Host／Origin／token 保护的退出接口；没有退出接口的旧版只在核对监听 PID、Python 进程名和本目录完整 server.py 路径后结束，不使用按名称结束所有 Python 的方式。旧版仍有调试连接或正在进行设备操作时先保留服务。

自动发现只读取当前 Windows IPv4 网关、已知设备地址与默认热点地址，并验证 `firmware/hardware/project_name`，不扫描整个网段，也不连接或切换 Wi-Fi。每次最多核查 4 个地址、每个 450 ms；尚未找到时页面每 4 秒再检测。默认密码只由后台发送给已验证的 RobotFish，不放进网页输入框、脚本、日志或浏览器存储。优先使用已保存密码，明确收到密码错误后才尝试出厂密码，不重试结果未知的登录请求。

地址和密码放在“自定义连接（可选）”中，日常不用展开。如果改过设备密码，输入一次并保留加密保存即可，后续自动使用 Windows DPAPI 保存的密码；RobotFish 保存规则与设备实际接受的 1～127 个可打印 ASCII 字符一致，旧探针的 12 位规则保留。已有本机控制会话会被复用；发现其他控制会话时，即使对方没有运动，自动连接也不会抢占，可手动点击“连接机器鱼”。后台重启后无法确认旧会话归属时，同样需点击接管，但无需重填已保存的密码。真实会话失效后不会循环自动夺回控制。

登录、退出和删除本机密钥与控制操作串行处理。退出会等待尚未完成的登录结束，再清除本机认证；页面丢弃退出后迟到的登录回包，避免重新显示已连接或恢复已删除的密钥。

服务启动后自动将诊断写入本目录 `logs/workstation.jsonl`，不添加到网页日志抽屉，也不弹提示。每份约 5 MiB，保留当前文件及 3 份历史文件（`.1`～`.3`）。后台队列异步落盘，队列上限 1024 条，磁盘堵塞时丢弃新日志而不阻塞控制。记录启动版本、请求状态与耗时、每秒 IMU 合法帧/字节增量、数据年龄、校验/接收错误、控制路由，以及浏览器异常和超过 100 ms 的主线程长任务。不记录 HTTP 请求正文、密码、Cookie 或控制会话。`server.log` 继续保留原有启动输出；排错优先查看 `logs/`，无需手动导出网页日志。

Windows 下发生设备传输错误时，后台最多每 30 秒采集一次无线诊断：读取最近两分钟的 Wi-Fi 连接/断开、受限连接自动恢复和接口移除/出现事件，以及当前接口 IPv4/网关，写入同一日志。采集独立运行，8 秒超时，不切换网络、不重启网卡、不修改配置。日志中的 `control_interrupted`、`telemetry_interrupted`、`control_link` 和 `windows_network` 可用于区分会话失效、应用超时与真实 Wi-Fi 掉线。

RobotFish 前台遥测按约 100 ms（目标 10 Hz）请求，慢请求完成后再继续，不堆积请求；隐藏窗口降为约 1 Hz。后台合并 75 ms 内的重复读取，遥测独立复用 HTTP 连接。已有手动数据记录仍为每秒一条。115200/8N1 是 IMU 串口吞吐配置，不等于传感器输出频率或网页刷新率；日志中的 `frames_per_s` 是加速度、角速度、姿态三类合法帧总速率。姿态年龄计入 HTTP 往返耗时和缓存停留时间，500 ms 过期判断保留；不会通过放宽过期阈值掩盖断流。

失败读取同样合并，逐步退避到最多 3 秒一次，恢复成功后回到正常速率，避免多窗口在断网时排队等待多个 1.5 秒设备超时。控制命令等待响应时不占用遥测状态锁，切换设备与控制命令仍串行，避免慢请求导致网页一起卡住。

在“设备设置”可以查看自动识别到的机器鱼，自定义地址才需要展开高级连接。单 ESP32-S3 身份为 `firmware=robotfish`、`hardware=robotfish-esp32s3`、`project_name=robotfish`。遥测免登录，六路值来自 `/motion_status` 的 `last_written`，表示驱动写入目标，不是位置反馈。无相机、STM32、DAP、SPI 管理链及电池采样时明确显示未提供。双链路固件（`lora_protocol=2`）使用 LoRa 主控、Wi-Fi 遥测与备用控制；旧版仅 Wi-Fi 固件按声明的能力开放控制。IMU 经 Wi-Fi 回传，不经过 LoRa 空口。

自动连接完成后可直接在“操控”页选择仿生、双螺旋桨或混合模式。首次获取控制会话先全停，不发送运动目标；需要人工按键才启动。按住方向按钮或 WASD 前后转向，R/F 浮沉，可同时按；按住每约150毫秒生成一个新序号目标，松开归零，空格或“全停”立即停止并回中。模式切换本身不启动或续期运动。

数据页连接后自动显示 IMU 三轴姿态、通信往返及实时曲线，不要求先开始记录；默认选择 IMU，另可选双桨、四舵机和延迟。实时预览复用原有遥测轮询，页面最多保留600条，不增加鱼端请求；切换设备会清空预览。机器鱼不再显示无关的 F405 采样面板，没有电池测量值时电压曲线禁选。连续角度显示只展开横滚／航向的 ±180° 边界，缺失样本仍断线；新固件的数字、表格和主曲线显示软件二阶低通后的传感器坐标角度；同步导出的 sensor_* 列始终保留原始值，roll/pitch/yaw 列保存显示值。

机器鱼的数据页将延迟明确标为“Wi-Fi 遥测往返”：从电脑发起 HTTP 状态请求到读完响应，包含网络和设备处理。该值来自 telemetry_rtt_ms，CSV／JSON 沿用 latency_ms 字段；控制走 LoRa 时也仍是 Wi-Fi 遥测耗时，不表示 LoRa 指令的空口或执行时延。生产 LoRa 没有接收 ACK；Wi-Fi 中断时无法从现有界面得出实时 LoRa 端到端时延。串口发送成功、排队完成和鱼端已执行应分别判断。

每个新收到的机器鱼遥测快照现自动写入 telemetry_sample 诊断记录（复用现有请求，不增加设备轮询），同时保存设备 uptime、原始／鱼体三轴、传感器样本龄与回传后年龄上界、四路舵机写入目标、双桨、输入目标和 LoRa 接收序号。数据页“舵机与姿态同步导出”通过 /api/data/synchronous/export 导出已有快照 CSV／JSON，无需开启原每秒记录；没有样本时明确报错，历史保留受现有日志轮转限制。舵机列表示驱动命令，不是位置反馈；未记录的旧舵机输出不能补造。

数据页将实时数字和曲线前置，隐藏重复的记录概览。点击图例可以单独隐藏／恢复某一轴，纵轴随所选曲线自动缩放；横轴和悬停按实际样本时间定位，断线间隔不会被挤成固定采样步长。

“视觉”页用于外接电脑摄像头或录像回放，当前机器鱼板没有板载相机，对应入口隐藏。原图输入预览、MP4与同步CSV、截图、二值阈值滑条、曝光、对比度、调试叠加、路径绘制／自动循迹、转弯采样均可使用；打开画面、绘制路径和采样不会启动运动，执行路线需要明确启动自动循迹。四点标定完成后主画面显示透视校正图，“显示视角”可切完整原图；框选机器鱼使用全局图，鱼头标定冻结并保留当前视角，透视点击按同一矩阵反算原图。预览默认15fps，可选3／10／15／30fps，鱼头标定后保持显示，主动关闭预览也不停止录像与采样。图像绝对定位于固定预览区域并完整缩放，避免Grid固有尺寸撑开轨道而裁切。

点击开始／停止CSV采样记录独立角度、X/Y、IMU与原生PID／执行器指令，导出CSV及包含各次标定的JSON；“采样与测试图文件”打开 `build/vision`。录像保存完整原图叠加与同步数据，文件正常结束后才标为已保存。正常停止视觉会收尾CSV和MP4，异常退出或磁盘错误不显示完整保存成功。

视觉使用本机已有 `D:/python/venvs/yolo/ultralytics/8.4.118/Scripts/python.exe`，可通过 `ROBOFISH_VISION_PYTHON` 指定已有 OpenCV／NumPy／Flask／Pillow 环境。回放默认读取工程同级的 `屏幕录制 2026-10-18 115851.mp4`，可用 `ROBOFISH_VISION_SAMPLES` 指定测试目录。

原来的“场地标定”直接完成四点透视，无需切换工作模式。当前实验按用户指定采用 4×2 米设定值；依次点击左上、右上、右下、左下，四边形映射到矩形坐标 `(0,0)、(4,0)、(4,2)、(0,2)`，原点在左上，x 向右、y 向下。矩阵自动保存到 `vision/configs/pool_calibration.local.json`；下次输入源、分辨率一致时自动加载，相机挪动后重新标定。尺寸标为 configured，不冒充实测值。重新标定清空视觉鱼头零位，需要重新点头；自动循迹会退出并请求全停，纯观测模式下不改变已发送目标。

点击“鱼头方向”后只冻结预览，后台继续采样。暗色厚身体像素先透视到米制场地，再拟合独立光学主轴；点头选择前后并建立视觉0°。实时相机按配置camera_latency_s（默认0.30s估计值）寻找图像对应IMU，建立同一参考；IMU增量不再次做透视。独立光学轴不使用IMU或运动方向，没有清晰视觉时留空。缺少对时或设备重启时不能同步控制零位；正常32位计时回绕保留参考。该光学轴并非已训练头部关键点的精度真值。

每次成功标定额外保存一张最长边1000像素的透视测试PNG（4×2时为1000×500）和矩阵JSON，位于 `build/vision`；场地标定卡片可下载。按用户最新要求，实时主预览也显示透视图，warp只在显示帧率内执行；YOLO、独立角度和位置仍使用完整原图及同一H。透视画面的鼠标点先反算回原图坐标，冻结标定则只接受原图坐标，避免坐标错配。`POST /api/vision/transform`复用缓存矩阵提供采样点换算。几何换算和测试图导出不发送机器鱼指令。

右上角“开始记录”启动后台每秒一条记录，切页后继续；停止后可以选择“记录回放”。CSV／JSON 导出全部保留样本，PNG 导出当前曲线，冻结只暂停图表，实时数字和后台记录继续更新。清空只删除已记录数据，不中断实时预览。表格显示 Roll／Pitch／Yaw、两路桨、通信往返和安全状态，电池未测时留空。新版后台修复了 Wi-Fi 往返延迟未写入记录，以及断线样本被错误记为其他来源、导致停止后无法续录的问题。

“yaw 角度闭环（默认关闭）”及 Kp、Ki、Kd 输入属于 S3 同一个角度 PID。点击应用后以鱼端回读为准，不把串口排队当作执行确认。参数仅更新 RAM；重启恢复 main/config/AttitudeConfig.h 的 Kp=5、Ki=0.02、Kd=0.1，yaw 范围±100%，原极性+1保持。指定航向执行中可单独调 PID；手动转向、配置接管和全停仍按原鱼端规则优先。

`2.6.1-yaw-hold` 开启后选择舵机与双螺旋桨混合模式，在首个有效 IMU 样本记录当前航向；即使没有前进目标，静止偏转也会驱动执行器纠偏。普通松键归零保留原目标和 PID；手动转向优先，松开后记录新航向，倒退仍手动。全停会关闭闭环并清除目标和积分，中立输出成功后也不自动恢复；IMU 失效／过期或重新开启会重新记录航向。姿态 PID 每 100 ms 在 S3 本地更新，现有 20 ms 摆尾分配、50 Hz PWM 保留；更新周期不是舵机转到目标所需的时间。yaw 的误差和 D 差分均按最短圆弧计算。用户侧航向显示保持左转增大，内部 FRD 与右转命令为正，并在显示／导出中明确区分。仅调 Kp/Ki/Kd 不启动闭环。

三轴使用同一 PID 实现和独立积分状态。pitch、roll 目前只计算预览，main/config/AttitudeConfig.h 的 kPitchOutputEnabled、kRollOutputEnabled 均为 false；实际执行器仍只接 yaw，roll 的鳍片几何和作用方向保持未标定。参数、论文依据、当前输出边界见 [三轴控制说明](../docs/guides/attitude-control.md)。

鱼端在 IMU 原有输出之后进行软件二阶低通：两个相同一阶状态，每级 3 Hz，按真实样本时间更新。roll、yaw 环绕处理，重复样本不推进滤波；中断后重新初始化。滤波结果同时用于 yaw 闭环和三轴显示，原始值不覆盖；滤波不消除陀螺零偏，也不能恢复通信缺失样本。水下阻力和惯性与地面不同，上述 PID／滤波值均为尚未水测整定的初值，静置数据不自动当作水平校准。

每次提交和鱼端确认的 PID 设置分别写入 logs/yaw-pid-history.jsonl，独立于轮转遥测日志保留；“导出调参记录”导出 CSV，记录 UTC、设备时间、开关、Kp/Ki/Kd、周期、滤波频率、通道和提交／确认区别。同步导出另外包含目标、角度误差、P/I/D、yaw 修正、pitch/roll 预览和执行器命令。没有鱼端回传时只记录提交，不伪造确认。

失焦、切页或隐藏窗口会清除按键并发送零目标。仅使用 Wi-Fi 控制时，临时超时、繁忙或回执丢失会保留控制认证，清除按键及未发送目标，界面显示“连接待验证”，暂停运动输入。“全停”在此期间仍可操作。恢复后只验证原会话，不自动重新获取控制权；确认全停后开放操控，必须重新按键，不续发旧目标。自动全停验证最多尝试 3 次，未确认时保持暂停，可在链路稳定后手动点击“全停”。密码错误、控制会话被其他终端接管、设备重启丢失会话或固件输出故障仍需手动重新连接 Wi-Fi 控制。已连接的独立 LoRa 不受 Wi-Fi 认证或遥测故障阻断。

鱼端 `2.6.0-yaw-pid` 取消 3 秒运动指令租约，最后有效指令保持至新目标或明确停止事件，兼容只在操作变化时发帧的遥控器；上位机仍按住操作、松开发送零目标。LoRa 的 3 秒主备健康判断不停止运动。页面根据鱼端 `motion_timeout_ms=0` 显示新策略，旧固件继续提示旧超时策略；只更新网页不能改变旧固件。鱼端同时修复控制循环旧时间早于 HTTP 入队时间时的无符号下溢，避免新指令被立即判为 `command_expired`；真正滞留超过 150 ms 的请求仍拒绝，不延迟执行旧动作。控制密码只保存在本地服务内存；勾选保存时才使用现有 Windows DPAPI 密钥存储。

Wi-Fi 控制接口为 `POST /api/v1/control`，由本地服务通过 `X-OTA-Password` 发送用户输入密码。`acquire` 使用随机 `session`；`target`、`mode`、`stop`、`attitude_on`、`attitude_off` 使用同一会话和严格递增的 `sequence`。姿态开关沿用 LoRa 主控／Wi-Fi 备用路由，并继续要求已知固件能力与标定。上位机不会重试失败的运动指令；Wi-Fi 控制入口不会向未声明 `wifi_control_allowed=true`、`control_protocol=1` 的旧固件开放运动控制。

多个上位机页面复用本机设备会话时，`/api/station/control`、`/api/station/target` 另带每页独立的 `client_id`，后端分别拒绝各页面的旧请求，再统一分配设备序号，避免另一页的全停被误判为旧请求。页面标识只供本机排序，不发到机器鱼或 LoRa；未传标识的旧调用仍保留原排序检查。

## 循迹调试终端与角度环

数据页新增持续滚动的调试终端，PC 行记录帧号、观测位置、视觉相对角、速度、LOS 航向和误差；FISH 行记录真实回传的 IMU、目标、PID 分项、转向请求、六路执行器指令与 LoRa 序号。支持暂停、来源筛选、清空、自动滚动及 TXT 导出，最多保留1000行；无数据用 —，仿真和录像分别标记，不伪装为实鱼反馈。

框选机器鱼与鱼头标定切换并保持完整全局画面，绑定冻结帧编号后按顺序处理鼠标事件。速度输入接受任意有限非负值，移除0.36m/s目标上限；该输入不是机器鱼达到对应速度的保证。

2.7.1固件默认 yaw PID 为2.5/0.02/0.1，±1°内清除I/D和转向纠偏，保留目标与推进。角度环的左右桨差动和尾舵转向分配提高到1.5倍，去掉该环原先随转向量平方额外削减前进量的处理；各电机饱和分配和机械边界仍生效。上位机从鱼端回读显示死区和分配增益，旧固件不填造这些字段。新参数需要手动升级新BIN，未自动烧录。

## 自动循迹

实时相机 → YOLO鱼框中心P → 四点H变换得到米制位置 → 局部单向路径投影 → LOS目标航向与弯道／末段速度目标 → 视觉速度PID给推进百分比 → Wi-Fi航向目标 → S3本地yaw PID及混合驱动。路径3cm重采样，前视距离直线24cm、弯道／偏离时缩至10cm，默认目标0.30m/s，距终点40cm开始减速，终点距离与剩余弧长均不超过20cm时请求全停。

“开始自动循迹 · Wi-Fi”明确接管，途中全停／人工输入会取消旧视觉任务。停止自动循迹、退出视觉、重新选鱼／标定／画线会退出自动控制。关闭预览或停止CSV采样不停止正在运行的自动循迹。完全断网时PC无法保证全停命令到达，鱼端仍沿用原先无运动超时的目标保持语义；终端和状态文字不把未确认的全停写成已停。此轮按用户要求未执行实机或回归测试，只做语法检查和固件编译。
