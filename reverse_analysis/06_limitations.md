# 局限与证据边界

## 这不是原始源码

固件没有携带 ELF 符号表和调试信息。报告中的函数名、结构体名和局部变量名是按行为重新命名；[05_recovered_pseudocode.cpp](05_recovered_pseudocode.cpp) 用于解释控制流，不能直接编译，也不能证明与原作者 C++ 逐行一致。

编译优化会内联函数、合并常量、复用寄存器并删除未使用分支。可以可靠恢复“做了什么”和大量数值边界，但通常无法恢复：

- 原始类名、源文件划分、注释和模板类型；
- 每个全局变量的原始名称；
- 浮点 CPG 公式在源代码中的书写形式；
- 编译前宏、条件编译分支和未进入最终镜像的功能。

## 工具限制

Rizin 0.9.1 用于全镜像交叉引用和交互数据库，但其 Xtensa 解码在这个镜像上会把部分合法指令显示为 `illegal`。关键函数因此使用官方 `xtensa-esp-elf-objdump` 2.43.1 重新验证。

Xtensa 指令长度可变，函数间填充和内联跳转表会使“从头到尾线性反汇编”失去指令边界。生成脚本把 Demo、failsafe 和 Partner 函数按已知分支入口拆开；`/control` 的相机参数分派仍包含跳转表，必须结合入口地址、分支目标和字符串交叉引用阅读，不能把表字节当作真实执行指令。

## 需要设备才能确认的内容

本次没有连接、烧录或运行硬件，因此无法静态确认：

- 相机传感器具体型号及运行时自动探测结果；
- 真实舵机方向、机械零位、鱼体姿态和水中动力学效果；
- 设备 NVS 当前保存的 Wi-Fi 和 Partner JSON；
- 分区表、当前/下一 OTA 槽及回滚状态；
- AP/STA 切换、断流重连和 failsafe 在实际射频环境中的时序抖动；
- 任务栈高水位、堆占用和长时间稳定性。

若后续允许连接测试设备，建议只做非破坏验证：先读取芯片/Flash/分区信息和串口启动日志，再在拆除推进负载或架空执行器的条件下验证 GPIO、模式、失联保护和 HTTP 响应。不要直接用恢复伪代码覆盖设备。

## 安全边界

- SoftAP 密码在镜像中是明文默认值 `12345678`；
- Wi-Fi 保存、驾驶和 Partner 控制接口未发现应用层认证；
- OTA 使用密码 SHA-256 比较，但摘要本身在固件中可读；本分析没有进行密码猜解；
- 应用镜像未加密，拥有固件文件的人可以读取网页、日志、常量和控制逻辑；
- 镜像 footer 的 SHA-256 是完整性校验，不是发布者身份签名。

这些观察描述的是固件的静态攻击面，不代表已经对设备实施入侵。部署到非可信网络前，应至少修改 AP/OTA 凭据、限制控制接口来源，并结合 Secure Boot、Flash Encryption 和签名 OTA 重新设计信任链。

## 与仓库 Driver SDK 的关系

`RoboFishPartnerDriverSDK` 可用作引脚和基础执行器行为的旁证，但它是另一个可编译固件，不包含 CameraTest 的摄像头、CPG、Demo、failsafe 和 Partner 引擎。报告没有把 SDK 源码冒充成 `CameraTest.ino.bin` 的原始源码；出现参数差异时，以预编译镜像中的直接指令为准。
