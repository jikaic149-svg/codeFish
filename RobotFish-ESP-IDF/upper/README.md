# RobotFish 工作站

本目录复用只读来源 `C:/Users/rlyoulo/Desktop/robofish_new/upper` 的顶层工作站源码，保留原作者信息。没有复制原工程的数据、模型 DLL、画像素材、EmberProbe 或固件工具。原目录未修改。

双击 `start.cmd`，或在本目录运行 `python -B launch.py`，打开 `http://127.0.0.1:8766/`。新服务身份为 `robotfish-local`，独立于旧工作站的 8765；不会结束其他目录或其他程序的进程。可用 `ROBOFISH_HOST_PORT` 同时调整启动器与服务端口。

本版源码服务修订为 `workstation-17-lora-sender-latency`，配套鱼端源码为 `2.5.1-attitude-hold`。连接 LoRa 串口后可独立手动控制，无需 Wi-Fi；连接机器鱼 Wi-Fi 后自动识别地址并建立控制连接，默认配置无需输入 IP 或 fishota。同目录旧版后台占用端口时，启动器核对服务身份和目录，结束旧版后启动新版；同版本则复用，不重复启动。仅刷新浏览器不能更新已运行的 Python 后台；重新打开启动器可以载入新版本，电脑网络无需切换。本轮未烧录或开启实鱼姿态辅助。

操控页常驻显示“LoRa 已连接／未连接／串口异常”和独立的 Wi-Fi 遥测状态。点击“连接设置”，最上方 LoRa 面板会扫描电脑串口，下拉列表显示端口编号和设备名称，由用户选择 LoRa 适配器后点击连接；没有默认端口，不会猜选第一个设备。插拔后点击“刷新串口”，仍存在的选择予以保留，已消失的选择清空；没有设备时提示接入 USB 转 TTL。扫描与选择都不打开串口，只有点击连接才打开用户所选设备；后端连接前再检查实际存在性，缺少端口或已拔出时直接提示重新选择，不回退到其他编号。参数仍为115200 / 8N1、鱼端地址 0x0102、信道 0x20，沿用当前鱼端 v2 CRC 协议。不要求先发现鱼、填写 IP、完成 Wi-Fi 登录或收到遥测，即可选择运动模式、按键／按钮操控及全停。Wi-Fi 中断不会清掉有效的 LoRa 按键；串口异常才清除旧输入，需人工重连并重新按键。断开／重新配置串口和退出后台前提交一次 STOP，重新连接只发心跳，不恢复旧目标。

“LoRa 已连接”表示电脑串口已打开；生产链路没有 LoRa 接收回执，没有 Wi-Fi 回传时显示“鱼端执行未确认”，IMU、执行器、安全状态继续留空／未知。发送统计独立从本机 `/api/station/lora` 读取；恢复 Wi-Fi 遥测后才显示鱼端接收状态，不用串口写入成功冒充鱼体已执行。

发送线程按提交事件唤醒并等待下次允许发送的时刻，去掉原50ms固定轮询。普通帧最小间隔仍为500ms；用户持续提交相同目标时，合并为每秒一次新序号续发，目标变化按原500ms间隔发送，STOP立即唤醒并优先提交。没有新的用户输入时不会自动重发运动目标。1秒续发兼容原3秒指令租约，未改变模块空中速率或接线。保持指令合并为变化指令腾出发送窗口，但连续快速改变目标仍可能等待约500ms。

数据页新增“LoRa 发送端耗时”，即使没有 Wi-Fi，也显示最近一次目标变化／设置的本机排队、USB串口写入和合计时间；不包含浏览器输入、空口传输或鱼端执行。相同目标的保持续发不覆盖最近操作的计时。后台 `lora_uart_tx` 日志另记每个控制帧的序号、字节数、排队／写入耗时和是否续发。串口写入完成不等于无线发送完成或鱼端收到。

右上角“退出上位机”会结束本机后台并释放端口；关闭浏览器标签只关闭页面。退出前会确认未导出的实验记录，向本机已持有的控制会话提交一次全停，再关闭 LoRa 串口；实际全停未确认时在退出页明确提示。没有打开页面时，可双击 `stop.cmd`，或运行 `python -B launch.py --stop`；`start.cmd --restart` 可重启。新版使用受本机 Host／Origin／token 保护的退出接口；没有退出接口的旧版只在核对监听 PID、Python 进程名和本目录完整 server.py 路径后结束，不使用按名称结束所有 Python 的方式。旧版仍有调试连接或正在进行设备操作时先保留服务。

自动发现只读取当前 Windows IPv4 网关、已知设备地址与默认热点地址，并验证 `firmware/hardware/project_name`，不扫描整个网段，也不连接或切换 Wi-Fi。每次最多核查 4 个地址、每个 450 ms；尚未找到时页面每 4 秒再检测。默认密码只由后台发送给已验证的 RobotFish，不放进网页输入框、脚本、日志或浏览器存储。优先使用已保存密码，明确收到密码错误后才尝试出厂密码，不重试结果未知的登录请求。

地址和密码放在“自定义连接（可选）”中，日常不用展开。如果改过设备密码，输入一次并保留加密保存即可，后续自动使用 Windows DPAPI 保存的密码；RobotFish 保存规则与设备实际接受的 1～127 个可打印 ASCII 字符一致，旧探针的 12 位规则保留。已有本机控制会话会被复用；发现其他控制会话时，即使对方没有运动，自动连接也不会抢占，可手动点击“连接机器鱼”。后台重启后无法确认旧会话归属时，同样需点击接管，但无需重填已保存的密码。真实会话失效后不会循环自动夺回控制。

登录、退出和删除本机密钥与控制操作串行处理。退出会等待尚未完成的登录结束，再清除本机认证；页面丢弃退出后迟到的登录回包，避免重新显示已连接或恢复已删除的密钥。

服务启动后自动将诊断写入本目录 `logs/workstation.jsonl`，不添加到网页日志抽屉，也不弹提示。每份约 5 MiB，保留当前文件及 3 份历史文件（`.1`～`.3`）。后台队列异步落盘，队列上限 1024 条，磁盘堵塞时丢弃新日志而不阻塞控制。记录启动版本、请求状态与耗时、每秒 IMU 合法帧/字节增量、数据年龄、校验/接收错误、控制路由，以及浏览器异常和超过 100 ms 的主线程长任务。不记录 HTTP 请求正文、密码、Cookie 或控制会话。`server.log` 继续保留原有启动输出；排错优先查看 `logs/`，无需手动导出网页日志。

Windows 下发生设备传输错误时，后台最多每 30 秒采集一次无线诊断：读取最近两分钟的 Wi-Fi 连接/断开、受限连接自动恢复和接口移除/出现事件，以及当前接口 IPv4/网关，写入同一日志。采集独立运行，8 秒超时，不切换网络、不重启网卡、不修改配置。日志中的 `control_interrupted`、`telemetry_interrupted`、`control_link` 和 `windows_network` 可用于区分会话失效、应用超时与真实 Wi-Fi 掉线。

RobotFish 前台遥测按约 100 ms（目标 10 Hz）请求，慢请求完成后再继续，不堆积请求；隐藏窗口降为约 1 Hz。后台合并 75 ms 内的重复读取，遥测独立复用 HTTP 连接。已有手动数据记录仍为每秒一条。115200/8N1 是 IMU 串口吞吐配置，不等于传感器输出频率或网页刷新率；日志中的 `frames_per_s` 是加速度、角速度、姿态三类合法帧总速率。姿态年龄计入 HTTP 往返耗时和缓存停留时间，500 ms 过期判断保留；不会通过放宽过期阈值掩盖断流。

失败读取同样合并，逐步退避到最多 3 秒一次，恢复成功后回到正常速率，避免多窗口在断网时排队等待多个 1.5 秒设备超时。控制命令等待响应时不占用遥测状态锁，切换设备与控制命令仍串行，避免慢请求导致网页一起卡住。

在“设备设置”可以查看自动识别到的机器鱼，自定义地址才需要展开高级连接。单 ESP32-S3 身份为 `firmware=robotfish`、`hardware=robotfish-esp32s3`、`project_name=robotfish`。遥测免登录，六路值来自 `/motion_status` 的 `last_written`，表示驱动写入目标，不是位置反馈。无相机、STM32、DAP、SPI 管理链及电池采样时明确显示未提供。双链路固件（`lora_protocol=2`）使用 LoRa 主控、Wi-Fi 遥测与备用控制；旧版仅 Wi-Fi 固件按声明的能力开放控制。IMU 经 Wi-Fi 回传，不经过 LoRa 空口。

自动连接完成后可直接在“操控”页选择仿生、双螺旋桨或混合模式。首次获取控制会话先全停，不发送运动目标；需要人工按键才启动。按住方向按钮或 WASD 前后转向，R/F 浮沉，可同时按；按住每约150毫秒生成一个新序号目标，松开归零，空格或“全停”立即停止并回中。模式切换本身不启动或续期运动。

数据页连接后自动显示 IMU 三轴姿态、通信往返及实时曲线，不要求先开始记录；默认选择 IMU，另可选双桨、四舵机和延迟。实时预览复用原有遥测轮询，页面最多保留600条，不增加鱼端请求；切换设备会清空预览。机器鱼不再显示无关的 F405 采样面板，没有电池测量值时电压曲线禁选。连续角度显示只展开横滚／航向的 ±180° 边界，缺失样本仍断线；数字、表格及导出保留传感器原始角度。

机器鱼的数据页将延迟明确标为“Wi-Fi 遥测往返”：从电脑发起 HTTP 状态请求到读完响应，包含网络和设备处理。该值来自 telemetry_rtt_ms，CSV／JSON 沿用 latency_ms 字段；控制走 LoRa 时也仍是 Wi-Fi 遥测耗时，不表示 LoRa 指令的空口或执行时延。生产 LoRa 没有接收 ACK；Wi-Fi 中断时无法从现有界面得出实时 LoRa 端到端时延。串口发送成功、排队完成和鱼端已执行应分别判断。

数据页将实时数字和曲线前置，隐藏重复的记录概览。点击图例可以单独隐藏／恢复某一轴，纵轴随所选曲线自动缩放；横轴和悬停按实际样本时间定位，断线间隔不会被挤成固定采样步长。

“视觉”页现在可用于机器鱼的外接电脑摄像头；当前板没有板载相机，对应入口隐藏。已接回现有 OpenCV 颜色跟踪运行文件，无需 PT 模型。选择摄像头索引或“录像回放”，点击“启动视觉控制”显示处理画面；录制独立于循迹，不需要启动循迹。点击“录制视频”后按钮变为“停止录制”，状态显示时长、写入帧数和丢帧；停止录制后自动保存 MP4 与对应 CSV，状态显示真实文件名。“录像与截图文件”打开当前工程 `build/vision`。停止视觉或退出上位机会收尾保存，编码器失败、空录像或异常退出会明确显示，避免仅显示已开始却没有可播放文件。

视觉默认使用本机已有 `D:/python/venvs/yolo/ultralytics/8.4.118/Scripts/python.exe`，可通过 `ROBOFISH_VISION_PYTHON` 指定已有 OpenCV／NumPy／Flask／Pillow 环境。回放默认读取同级 `codefish/VISION/auv_record_*.mp4`，可用 `ROBOFISH_VISION_SAMPLES` 指定目录。运行代码来源为同级 `robofish_new/vision`，来源摘要记录在本工程 `vision/origin.json`，原目录保持不变。

右上角“开始记录”启动后台每秒一条记录，切页后继续；停止后可以选择“记录回放”。CSV／JSON 导出全部保留样本，PNG 导出当前曲线，冻结只暂停图表，实时数字和后台记录继续更新。清空只删除已记录数据，不中断实时预览。表格显示 Roll／Pitch／Yaw、两路桨、通信往返和安全状态，电池未测时留空。新版后台修复了 Wi-Fi 往返延迟未写入记录，以及断线样本被错误记为其他来源、导致停止后无法续录的问题。

新增“姿态辅助”开关，默认关闭。开启入口同时检查本地后台 `features.attitude_control`、鱼端支持声明、安装映射与执行器标定状态；旧后台、旧固件或未标定时保持不可开启，设置被拒绝不会清除原有人工控制认证。辅助只在有效前进期间作用，提供俯仰、横滚稳定及相对航向保持；手动浮沉或转向优先，松开转向后保持当时方向。全停、失效或重新开启会清除旧航向目标，开关本身不启动或续期运动。

姿态区域显示各轴标定／工作状态、鱼体姿态、三轴修正及相对航向目标；原 IMU 区域继续显示传感器原生坐标。过期状态不会继续显示为正在辅助或航向已锁定。每秒诊断同时记录这些字段，仍使用原有静默本地日志。用户确认左转 yaw 增大、抬头 pitch 减小、右翻 roll 增大；结合日志中静置 roll 接近 ±180° 配置安装映射，统一处理跨零和 ±180°。精确水平零偏仍待实测，日志中的 4°／7° 倾角不自动归零。辅助默认关闭，横滚鳍片纠偏未标定时不输出，未做水池参数整定。

失焦、切页或隐藏窗口会清除按键并发送零目标。仅使用 Wi-Fi 控制时，临时超时、繁忙或回执丢失会保留控制认证，清除按键及未发送目标，界面显示“连接待验证”，暂停运动输入。“全停”在此期间仍可操作。恢复后只验证原会话，不自动重新获取控制权；确认全停后开放操控，必须重新按键，不续发旧目标。自动全停验证最多尝试 3 次，未确认时保持暂停，可在链路稳定后手动点击“全停”。密码错误、控制会话被其他终端接管、设备重启丢失会话或固件输出故障仍需手动重新连接 Wi-Fi 控制。已连接的独立 LoRa 不受 Wi-Fi 认证或遥测故障阻断。

鱼端 `2.5.1-attitude-hold` 取消 3 秒运动指令租约，最后有效指令保持至新目标或明确停止事件，兼容只在操作变化时发帧的遥控器；上位机仍按住操作、松开发送零目标。LoRa 的 3 秒主备健康判断不停止运动。页面根据鱼端 `motion_timeout_ms=0` 显示新策略，旧固件继续提示旧超时策略；只更新网页不能改变旧固件。鱼端同时修复控制循环旧时间早于 HTTP 入队时间时的无符号下溢，避免新指令被立即判为 `command_expired`；真正滞留超过 150 ms 的请求仍拒绝，不延迟执行旧动作。控制密码只保存在本地服务内存；勾选保存时才使用现有 Windows DPAPI 密钥存储。

Wi-Fi 控制接口为 `POST /api/v1/control`，由本地服务通过 `X-OTA-Password` 发送用户输入密码。`acquire` 使用随机 `session`；`target`、`mode`、`stop`、`attitude_on`、`attitude_off` 使用同一会话和严格递增的 `sequence`。姿态开关沿用 LoRa 主控／Wi-Fi 备用路由，并继续要求已知固件能力与标定。上位机不会重试失败的运动指令；Wi-Fi 控制入口不会向未声明 `wifi_control_allowed=true`、`control_protocol=1` 的旧固件开放运动控制。

多个上位机页面复用本机设备会话时，`/api/station/control`、`/api/station/target` 另带每页独立的 `client_id`，后端分别拒绝各页面的旧请求，再统一分配设备序号，避免另一页的全停被误判为旧请求。页面标识只供本机排序，不发到机器鱼或 LoRa；未传标识的旧调用仍保留原排序检查。

“开发”页为识别到的 RobotFish 显示 Wi-Fi OTA。选择本工程的 `build/robotfish.bin` 并手动输入现有 OTA 密码，不预填密码。PC 检查 ESP32-S3、`robotfish` 项目名、0x330000 字节上限、镜像段边界、校验和与附加 SHA256；这是完整性检查，BIN 没有签名。设备接收后，必须同时报告目标版本、应用槽切换与 `ota_confirmed=true`、`runtime_ready=true` 才显示完成。同版本重刷也要求换槽。首次 USB 安装使用工程的 `idf.py flash`。

旧 `rlyoulink` 的 Cookie 登录和 `.amphipkg` 路径保留。独立复制的本目录不包含其签名工具；需要时设置 `ROBOFISH_FLASH_HOME` 指向旧工程 `embedding/s3/tools`。旧 STM32 离线模型与 EmberProbe 功能未随本交付提供。

离线检查：`python -B -m unittest discover -s tests -v`。测试使用本机临时 HTTP 夹具，不接触硬件。实际 2.4G、执行器和 OTA 重启仍需上板验收。

如本机已安装 Playwright 与 Edge，可运行 `python -B tools/verify_browser.py` 检查页面六路数据、BIN 选择与模拟 OTA；脚本仅访问本机临时端口，不占用 8765/8766。

运行 `python -B tools/verify_realtime.py` 验证约 10 Hz 遥测、连接复用、操控/记录、断网/回执丢失后的会话保留、旧目标不重放、恢复次数上限、真实接管退出、慢响应过期与静默日志。仅创建本机临时 HTTP 夹具和独立的无界面 Edge，不操作电脑网络或现有上位机服务，也不打开真实串口。

`python -B tools/verify_lora_standalone.py` 使用真实网页、后台与发送线程，配合假 UART 和本机模拟鱼，验证串口枚举、无设备、多个端口手动选择、刷新保留、消失后清空和选择不自动打开；随后验证无 Wi-Fi 登录的 LoRa 状态、模式、组合方向、松开、全停，Wi-Fi 中断后继续控制，串口写入失败、重连不重放旧目标；实际校验 UART 地址头、CRC 和三轴数值。截图位于 `build/host-lora`，不打开真实串口。

`tools/measure_lora_sender.py --port <已确认的串口> --output <结果JSON>` 是显式真实串口测量工具，只发送 STOP、零目标与心跳，支持 `--implementation` 对比原发送器快照。运行前需断开上位机对此串口的占用；工具沿用发送源和持久序号文件，停止时提交STOP并关闭串口。结果区分全停、限速零目标、保持后目标变化，时间范围为提交发送器到 Windows 串口写入完成，不测鱼端接收。2026-10-24 COM13／CH340实测，8轮的中位数：全停33.273→1.539ms、保持后新变化358.878→1.497ms；连续限速场景379.661→380.479ms，仍受500ms间隔约束。此次仅改变零目标的推进比例以模拟新目标，不发送非零运动。报告位于 `build/host-lora/latency/com13-before-full.json` 和 `com13-after.json`；当前没有LoRa回执，未把这些数值当作空口或鱼端执行时间。

`python -B tools/verify_data.py` 验证未记录时的实时曲线、连续角度、冻结／恢复、过期与断线缺口、切页后台记录、CSV／JSON／PNG、清空与移动布局；测试不发送运动目标。桌面和移动预览保存在工程 `build/host-data/data-desktop.png` 与 `data-mobile.png`。

在上述 OpenCV 环境运行 `python -B vision/test_video_recording.py`（工程根目录）检查真实编码／解码、尺寸、CSV、编码失败与空录像。`upper/tools/verify_video_recording.py` 通过真实视觉子进程录制合成视频并重新解码，验证源帧去重、FPS、主动停止和退出保存；随后用工作站 Python 运行 `upper/tools/verify_vision_browser.py` 验证网页按钮和保存状态。所有测试不打开摄像头，不发非零运动目标，输出位于 `build/host-vision`。

`python -B tools/verify_autoconnect.py` 在本机模拟鱼上验证不填地址/密码即可连接、多页面全停与独立排序、尊重其他空闲会话、手动接管、不自动夺回控制、自定义密码只输入一次、自动/手动登录迟到回包不能撤销退出，以及密码不进入网页或日志。`tests/test_server_sessions.py` 在本机 HTTP 接口交错执行登录与退出，验证认证和密钥保存先完成，退出最后生效。测试密钥只保存在临时目录，结束后删除，不写入真实用户密钥文件。

无线省电核查脚本为 `tools/network_stability.ps1`，默认 `-Mode Audit` 只读。`-Mode Stage` 仅对已核查的 Realtek 8922AE 保存标准 Windows 无线电池省电档位为最高性能，先备份至工程 `validation/windows-wifi-policy.json`，不调用电源计划重新激活、网卡重启、SSID/IP 修改或驱动安装。调整留待电源策略下次加载；不能据保存成功认定当前掉线已根治。`-Mode Restore -WhatIf` 可预演回滚，去掉 `-WhatIf` 恢复备份档位，同样不重新激活计划。PowerShell 限制脚本运行时，可仅对此进程使用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/network_stability.ps1 -Mode Audit`，不更改全局执行策略。

`python -B tools/verify_attitude.py` 用本机模拟鱼验证默认关闭、未标定／旧固件／旧后台兼容、设置不启动运动、人工浮沉和转向优先、松开后重记航向、失效撤除辅助、倒车与原地转向保持人工控制。该脚本不打开真实串口，不连接实鱼，不更改电脑网络。从工程根目录运行 `python -B tests/wifi_http/telemetry.py`，可编译实际遥测构造代码并检查包含姿态字段后的 4096 字节响应容量和运行时波特率显示。
