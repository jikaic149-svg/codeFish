# 视觉侧优化实施计划

## 1. 目标与边界

- 当前阶段已由纯 `PROP` 改为 `HYBRID`：螺旋桨提供持续推进，双尾舵与螺旋桨同向增强转向。
- 当前已同步修改 MCU 控制端；不增加 IMU。所有新闭环行为仍需实机水下验收。
- 先保证视觉位置、速度、运动航向和左右极性可信，再启用新闭环控制器。
- 第一版不测量鱼体艏向和侧滑角。普通 YOLO 水平框与单个色块只能提供位置，不能可靠区分鱼头/鱼尾。
- 启动前由用户在画面中点击“鱼尾 -> 鱼头”，提供初始航向；鱼被人工搬动后重新输入。

## 2. 当前已确认的问题

1. 相机主循环会重复读取同一份较慢的 YOLO 结果，但速度计算使用新的相机帧时间，容易产生零速度与尖峰。
2. 当前 `Dir` 只是相邻位置的运动方向，没有有效性和拟合质量说明。
3. YOLO 水平框中心、鱼体轮廓质心和自然色块质心都不是鱼体固定点；鱼转向、侧翻、遮挡和框尺寸变化时会相对鱼体漂移。
4. 路径控制只使用横向误差和剩余距离，没有把当前运动航向用于转向。
5. 视觉通信存在 STOP 与旧 HTTP 请求并发晚到的风险。
6. 相机、YOLO、跟踪、控制、记录和显示集中在一个文件中，后续修改容易互相影响。

## 3. 固定参考点与 YOLO/OpenCV 融合方案

### 3.1 质心不能保证相对鱼体绝对不变

- YOLO 框中心是检测框几何中心，不是鱼体上的物理点。
- 鱼体轮廓质心会随可见轮廓、反光、遮挡和姿态变化。
- 从鱼自身颜色提取的自然色块质心也会随阈值和可见面积变化。
- 单目顶视相机加平面单应矩阵还会受到鱼的深度和侧翻影响，因此视觉系统不能承诺“绝对不变”，只能给出误差范围和失效状态。

推荐做法不是继续优化“鱼的质心”，而是定义一个鱼体固定参考点：

- 在鱼体中央、顶部可见位置固定一个面积足够的刚性圆形/方形色标。
- 色标的物理中心就是控制位置，尽量放在希望跟踪的鱼体中心位置，使安装偏移接近零。
- 路径误差、速度和运动航向全部使用色标中心，不再使用 YOLO 框中心作为米制位置。
- YOLO 框只负责确认目标身份、限制色标搜索区域和失效后重新捕获。
- 色标轮廓部分遮挡、面积异常、圆度/矩形度异常或HSV质量下降时，参考点直接标记为 `INVALID`，禁止用漂移质心继续闭环。

如果不能安装固定色标，只能使用降级模式：YOLO框中心、自然色块和运动预测融合得到“估计参考点”。该模式不能保证相对鱼体固定，必须在日志和OSD中明确标记为 `ESTIMATED`，且不用于最终PWM—速度精标定。

可选的长期替代方案是训练鱼头、鱼尾和鱼体中心关键点模型；普通水平框不能解决固定参考点问题。

### 3.2 分层融合

采用“YOLO 全局锚点 + OpenCV 色块短期跟踪 + 运动预测”的分层结构：

- YOLO/BoT-SORT：负责确认目标身份和给出色标搜索区域，不把框中心直接当作鱼体位置。
- OpenCV HSV 阈值/反向投影与轮廓中心：跟踪固定刚性色标，在两次 YOLO 更新之间提供高频参考点。
- 常速度卡尔曼预测：在短暂缺测时保持连续位置，并为异常检测提供预测值。
- 融合门控：色标中心相对预测突变过大时不立即接受；YOLO框突然变化时只更新搜索区域，不直接拉动鱼体位置。
- 色块失效：面积、饱和度、轮廓形状、直方图相似度或搜索窗口越界时立即失效，不允许自然色块长期单独漂移。
- YOLO 重新捕获后重新初始化色块模型和搜索窗口。

色块跟踪的使用条件：

- 优先使用固定在鱼体中央、颜色稳定且与水面背景区别明显的专用色标。
- 初次使用时由用户框选色标 ROI，程序记录 HSV 范围、面积和轮廓形状；配置可保存，同一光照下复用。
- 若没有稳定色块，系统必须允许关闭色块辅助，仅使用 YOLO 与运动拟合。
- 单个色标只提供固定位置参考，不用于宣称鱼体艏向或侧滑角。

## 4. 分阶段实施

### 阶段 0：基线与离线验证入口

状态：离线入口与纯算法模块已实施。

- 保留当前视觉脚本作为行为基线。
- 为坐标、时间戳、角度归一化、轨迹误差和跟踪门控提取可独立测试的纯函数。
- 允许从已有录像/合成轨迹离线运行测量模块，不需要连接机器鱼。

验收：Python 语法检查通过；基线功能和按键不变。

### 阶段 1：建立鱼体固定参考点与融合跟踪

状态：橙色色标框架已实施并作为当前唯一控制参考；白色刚性鱼身识别暂时关闭。

- 增加专用色标 ROI 采样、HSV 模型、轮廓中心和质量评分。
- 将“鱼的位置”明确定义为刚性色标物理中心，而不是 YOLO 框中心或自然轮廓质心。
- YOLO只负责身份确认、搜索区域和重新捕获；色标负责高频位置；预测负责短时连续性。
- 记录位置来源：`MARKER`、`PREDICTED`、`ESTIMATED_FALLBACK` 或 `INVALID`。
- 对面积、轮廓形状、颜色质量、边界裁切和位置突变设置门控；失败时不输出伪精确位置。
- 无专用色标时允许降级测试，但禁止把降级数据用于最终PWM—速度映射。

验收：固定鱼体并改变YOLO框大小时参考点不随框中心移动；人工绕色标中心转动鱼体时参考点漂移不超过设定像素阈值；遮挡色标时输出 `INVALID` 而不是漂移位置。

已完成的框架（2026-08-14）：

- 新增 `fixed_reference_tracker.py`，实现 ROI 采样、环形 Hue 模型、HSV 掩膜、轮廓中心、面积/形状/颜色/边界/突变门控、常速度短时预测及本地配置保存。
- YOLO 结果保留真实 `bbox`；有色标模型时框中心不再参与精确位置计算，只负责身份确认、搜索范围和重新捕获。
- 色标有效时输出 `MARKER`；瞬时缺测输出不可用于精标定的 `PREDICTED`；随后输出无坐标的 `INVALID`。没有色标模型时才允许 `ESTIMATED_FALLBACK`，且明确禁止进入 PWM—速度精标定。
- 主画面和 JSON 已显示位置来源、质量、门控原因和 `usable_for_pwm_speed`；无效速度/方向显示 `INVALID`，不再伪装成零。
- 新增画面底部可点击工具栏：`START`、`STOP`、`CLEAR PATH`、`MARKER ROI`、`POOL CALIB`、`REC`、`SNAP`、`CLAHE`、`EXP -`、`EXP +`、`EXIT`。键盘只保留兼容快捷键。
- 11 项离线合成测试通过，包括 YOLO 框缩放不拉动色标中心、鱼身绕色标旋转、假色块突变拒绝、短时遮挡后失效、边界裁切拒绝、YOLO 重捕获、配置读写、按钮命中和工具栏渲染范围测试。

等待实物完成的项目：

- 用户连接摄像头并提供固定鱼、不同角度、不同光照、反光和部分遮挡照片后，确定专用色标的实际颜色与安装位置。
- 根据真实像素面积和噪声调整 HSV、面积比、形状、边界、跳变和预测时限；当前数值只是保守初值。
- 在真实画面测量旋转漂移像素阈值并执行本阶段三条实物验收。在通过前不把阶段 1 标记为完成，也不进入阶段 2。

当前有效约定（2026-08-15）：为优先跑通实机，控制位置暂时只使用橙色鱼尾中心；白色刚性鱼身检测保留在模块中但运行时关闭。橙色块位于摆动鱼尾，因此数据不得用于最终 PWM—速度标定。YOLO 以 5 Hz、`0.18` 置信度做纯检测和全局重捕；橙色色块逐相机帧独立跟踪，短时缺失最多预测约 `0.45 s`，只有色块与预测都失效才取消闭环。位置使用约 `0.40 s` 短窗口直线拟合输出 `vx/vy`，拒绝超过 `0.80 m/s` 的不可能色块尖峰；运动航向使用约 `0.60 s` 窗口、至少 `0.25 s` 数据、速度高于 `0.08 m/s` 才更新，并以 `0.20` 融合，避免摆动鱼尾在单次更新中扭转控制坐标。三次屏幕秒表测试得到约 `0.13/0.26/0.53 s` 总相机显示延迟，配置采用均值附近的 `CAMERA_LATENCY_S=0.30`；轨迹控制位置按 `vx/vy` 向前预测 0.30 s，补偿距离最大 0.12 m。控制器在前方 `0.32 m` 内用两段平滑弦线估算带符号真实曲率 `κ`（单位 `m⁻¹`），总转向明确拆为“曲率前馈 + 轨迹切线航向误差 + 带符号离轨误差”。网页 HYBRID 满转直径约 `0.40 m` 只作为第一版参考，取估计最小半径 `0.20 m`、估计最大曲率 `5.0 m⁻¹`；曲率前馈按 `κ×0.20` 连续映射并限幅，待视觉转圈拟合后替换，不把估计值当精确标定。前视距离在离轨前即随曲率、并在离轨后随距离，从 `0.24 m` 连续缩到 `0.10 m`。总转向 `±1` 映射为视觉 X `±0.333 m`，配合 MCU `Kp=300 %/m` 精确开放 `±100%` 转向，不再使用曲率放大航向误差的 `0.45~1.90` 经验增益。固件按实际总转向需求连续混合动力：直线鱼尾74%/螺旋桨100%，满转锚定网页 HYBRID 的鱼尾75%/螺旋桨75%，不再在满转时把二者削到60%/20%。正后方只锁定掉头符号，不再在120°切换增益。距终点和剩余路径均进入 `0.40 m` 时请求柔性反转制动；制动结束仍在 `0.20 m` 停止圈外时，以26%限流动力保留最新转向低速重新接近，反转阶段螺旋桨转向保持中位；进入 `0.20 m` 后电脑发送渐变 STOP。

### 阶段 2：修正时间戳、速度和运动航向

状态：短窗口速度/航向拟合已实施；残差质量输出仍待实施。

- 只在新的参考点时间戳到达时更新物理位置与运动状态，不重复消费同一YOLO结果。
- 使用最近约 `0.40 s` 的带时间参考点做线性拟合，输出 `vx`、`vy`、速度和运动航向。
- 目标 ID 改变、参考点来源降级、检测间隔过长或位置跳变时重置拟合窗口。
- 速度低于约 `0.04 m/s` 时不使用运动航向更新控制。
- 输出拟合跨度、样本数、残差和位置来源，禁止用 `0 deg` 冒充无效航向。

验收：静止参考点不出现周期性速度尖峰；匀速合成轨迹速度和航向误差在设定容差内；注入YOLO框跳变不改变速度结果。

### 阶段 6：HYBRID 路径控制器

状态：真实曲率前馈、独立航向/离轨反馈和连续动力混合软件框架已实施；实机验收仍待进行。

- 轨迹按 3 cm 等距插值；前视在离轨前随估计曲率、离轨后随距离，从 0.24 m 连续缩短到 0.10 m。
- 航向误差改为鱼头相对轨迹切线的夹角；离轨项改为带符号距离的几何反馈，二者不再重复藏在前视点 LOS 角中。
- 用前方 4～12 cm 与约 20～32 cm 两段平滑弦线的有符号夹角除以实际跨度，输出 `m⁻¹` 曲率；无实测数据时以目测满转半径约0.20 m建立回退前馈 `κ×0.20`。
- 底部【转圈测量】按钮提供被动实测框架：按一次开始，用户仍在网页手动保持 HYBRID 满左或满右至少半圈，再按一次自动拟合。只接收橙色色块直接 `MARKER`，拒绝 `PREDICTED`、YOLO降级、样本不足、圆弧不足、方向反复和高残差数据。
- 左右满转半径分别保存到本地 `turn_calibration.local.json`；路径正曲率使用左转实测半径，负曲率使用右转实测半径，缺失的一侧继续回退0.20 m。圆拟合使用稳健权重和MAD门控抑制鱼尾摆动、反光与少量跳点。
- 总转向为“曲率前馈 + 航向反馈 + 离轨反馈”并限幅 `±1`；对应视觉 X `±0.333 m` 和 MCU `Kp=300 %/m` 的 `±100%` 转向。
- 起步使用人工鱼头方向；产生可靠位移后用平滑运动航向更新。
- 普通转弯不做延迟速度闭环；动力随实际总转向从直线鱼尾74%/螺旋桨100%连续过渡到网页满转鱼尾75%/螺旋桨75%，不反转。
- MCU 的 X 控制采用 `Kp=300, Ki=0, Kd=0`；曲率前馈在误差出现前转向，航向和离轨项只修正剩余偏差。
- 运动航向用0.60 s窗口、至少0.25 s数据和0.20融合；正后方只保持首次掉头方向，不在120°切换另一套增益，也不在 `±180°` 边界换向。
- 0.40 m内终点柔性反转制动，0.20 m内渐变STOP；制动结束仍在圈外时用26%限流档保留转向低速重新接近，反转阶段螺旋桨转向中位。
- 不增加新的普通转弯状态机或终点捕获锁存。
- 视觉启动时先确认 `HYBRID`；`/vision_pid` 在 MCU 内也固定保持 `HYBRID`，防止首帧又切回 `PROP`。
- X PID 同时产生双尾舵转向偏置与螺旋桨转向；Y PID 同时决定尾舵摆幅和螺旋桨油门。

验收：合成水平、垂直、斜线和折线路径的左右极性正确；合成左右圆、鱼尾周期扰动和少量跳点拟合测试通过；实机分别完成满左、满右至少半圈测量，并核对终端报告的直径、圆弧覆盖和RMS残差。实机路径测试从低动力短轨迹开始。

## 5. 每一步的执行规则

1. 每次只把一个阶段标记为“进行中”。
2. 修改前记录目的、输入输出和不变边界。
3. 先完成纯函数/离线测试，再运行主程序。
4. 不通过当前阶段验收，不进入下一阶段。
5. 每个阶段完成后更新本文件状态，并在根目录 `process.md` 记录修改、验证、限制和待确认事项。
6. 连接实机、下发动力、烧录固件或删除导出数据前另行确认授权。
