# 指定航向调试与独立视觉观测

当前上位机为 `workstation-23-heading-observer`，鱼端航向接口为 `2.7.0-heading-target`。按用户最新要求，生产视觉入口为 `upper/vision_service.py → vision/observer_runtime.py`：只做鱼体识别、透视标定、独立角度／轨迹采样和遥测读取。手动点击操控页“发送目标角度”才提交目标，S3 使用本地 IMU 闭环。视觉不执行 LOS、速度 PID 或角度控制；旧引导代码仅保留给离线仿真，不从网页启用。

## 实验流程

1. 使用具备 `heading_target_supported` 的 S3 固件，连接控制通道及 Wi-Fi 遥测；新上位机需要重新运行 `upper/start.cmd`。未更新固件时不能靠刷新网页获得新接口。
2. 启动实时相机，在原有“场地标定”依次选左上、右上、右下、左下。当前实验按用户指定使用 **4×2 米设定值**；尺寸比例影响角度，不能当作实测尺寸。
3. 鱼头方向清晰时点击“鱼头方向”，再点击冻结图像里的头端。冻结只影响预览，后台继续处理新图像，以保持视觉身份连续。建议静止标定。
4. 独立视觉轴与图像对应 IMU 同时建立零位。实时相机的有效配对可自动同步到操控页；同步只保存 PC 坐标参考，不更改鱼端现有目标。没有视觉也可点击“当前 IMU 设为 0°”。
5. 输入左转为正的目标角度与前进幅度，点击发送。默认先确认视觉 CSV 采样启动，再发送一次目标。S3 持续执行本地闭环，前进幅度为0时仍能调试静止角度保持。
6. 停止采样后下载 CSV 和 JSON，文件保存在 `build/vision/heading-*.csv/json`。**停止采样／视觉不停止鱼**；停止运动使用“全停”。准备采样期间出现全停、手动输入或控制配置变化时，取消尚未发出的角度目标。

录像回放仅产生视觉角度和轨迹，不绑定当前实鱼 IMU，也不能建立实鱼控制零位。采样表中的 IMU、目标和执行器列在回放时留空。

## 坐标、角度与透视

场地原点在左上，x向右、y向下；世界航向逆时针／左转为正。S3 的 `body_yaw_deg` 是安装映射后的局部顺时针航向，不代表地理北。

四角建立像素到米制的 H。位置与参与视觉轴拟合的身体像素先经 H 换算到场地坐标；不能直接把原图斜率当作实际角度。独立视觉角度来自 YOLO 鱼框内暗色身体轮廓的加权主轴，厚身体区域权重大于细尾，手动点头只解决前后180°歧义。它不使用 IMU 或位移方向，属于身体主轴观测，并非训练得到的头部关键点真值。遮挡、轮廓不清、轴不明确、身份变化或长时间失去视觉连续性时，角度无效；不以 IMU 填补视觉角度。

标定图像中的视觉世界轴为 `psi0`，对应 IMU 为 `yaw0_cw`：

```text
visual_relative_left = wrap(visual_world_axis - psi0)
imu_relative_left    = wrap(yaw0_cw - body_yaw_cw)
manual_target_cw     = wrap(yaw0_cw - requested_relative_left)
visual_error        = wrap(target_relative_left - visual_relative_left)
```

目标只转换一次到 S3 局部航向。IMU 转角不经过 H。可选原图预览中紫色 VISION 为独立视觉轴，绿色 IMU 为对齐后的 IMU 方向，黄色 TARGET 为已回读目标；箭头各自的世界起点／终点统一经逆H投回原图。

场地重标定只更新观测几何、清空视觉零位并要求重新点头，不改变已发送的鱼端目标。每段 CSV 保存场地／鱼头标定ID，JSON保存对应矩阵、尺寸、源与零位快照，重标定前后的数据不能混用角度零位。设备 uptime 回退使 IMU 控制参考失效，正常32位回绕保留参考。

H按固定相机、近似同一观测平面建立，不补偿水深、折射、镜头畸变和相机移动；换相机位置后重新标定。

## 时间与采样

相机接收时间减去 `vision/configs/control.json` 的 `camera_latency_s`（默认沿用0.30s）作为估计采样时间，**不是硬件曝光时间**。IMU保存最多128份有效历史，按短圆弧插值，超过原0.35s对齐窗口时标无效。实际相机延迟需实验测定；配置误差和IMU滤波滞后仍会影响快速转动对比。

角度按传感器样本时间插值；目标、控制零位和执行器命令按遥测快照时间保持阶梯值，不从未来快照取命令。CSV保留相机接收／估计采样时间、视频时间、IMU时间、插值跨度、原生遥测时间与设备uptime，以便后续检查时间误差。没有同一鱼头标定ID和有效时间配对时，不计算视觉与 IMU／目标的比较误差。

每个实际处理的相机帧最多写一行，包含独立视觉世界／相对角度、X/Y轨迹、有效性／原因、主轴质量、YOLO置信度及跟踪来源、IMU、目标、PID误差和P/I/D、推进、尾舵／双桨命令、LoRa序号与阶段耗时。执行器列是驱动命令，不是实际位置或推力反馈；缺失值留空。插值不提高 IMU 的真实采样频率。

CSV每秒刷新，停止／正常退出后收尾保存；保存错误和异常退出不标为完整成功。导出仅允许本轮输出目录内的已停止完整文件。元数据同时保留模型路径／SHA256、相机时延设定和各次标定。

## 性能与界面

正常循环仅转换采样点／身体像素，不逐帧 warp 整幅图。每次四角标定只保存一张最长边1000像素的透视测试PNG和矩阵JSON；原有卡片可下载，`/api/vision/transform`复用同一H进行点变换。

原图预览最高3fps，标定后默认关闭并收起画面区域，后台识别与CSV继续。采集用单个最新帧，旧帧不会排队积压；每个新帧只识别一次，相同冻结／结束图像不重复JPEG编码。省去旧界面逐帧中文HUD绘制、双路JPEG和MP4编码；光流特征提取改为鱼体局部区域，保留边缘滤波余量和原图坐标，避免稀疏mask仍让特征计算扫描整图。未改变 `.pt`、960输入尺寸、0.25阈值或FP32精度。网页列出检测、光学轴、预览耗时及丢弃采集帧数，3fps预览不能当作识别帧率。

本机实际视频的300帧离线基准（排除20帧预热）使用RTX5060 Laptop GPU。优化前，GPU推理均值约7ms，特征提取等检测外工作约13ms，整条链约26～27ms（约37fps）。局部特征提取后，检测外工作降到约0.9～1.0ms，GPU推理约7ms不变，完整检测约12ms，独立光学轴约0.6ms，包含解码和CSV的整条链约14.4～14.6ms（约68～69fps）。3fps预览均摊约0.2ms；预览开关差异小于这次运行波动。数字是当前视频的离线处理能力，源视频仍为30fps，不能代替真实摄像头延迟或水中闭环效果。

PC总算力不能直接等同于单路视觉速度：解码、缩放／CPU到GPU传输、框结果回读、跟踪、显示和网络有串行部分，小模型单帧GPU工作后还要等待这些阶段。CPU总利用率低也不表示关键线程没有瓶颈。先看阶段耗时和图像年龄，再决定是否降低检测尺寸或改变模型；本轮未做模型转换或量化。

## 验证与已有固件

`upper/tests/test_heading_observer.py` 用合成图验证强透视的轴拟合、独立性、丢失失效、时间配对、未来目标隔离、回放隔离、CSV收尾及只读接口。`upper/tools/verify_vision_cascade_browser.py` 使用真实视频／YOLO和明确模拟的控制端验证网页标定、预览关闭、手动一次目标、全停取消待发目标及导出；不打开真实摄像头／串口。`upper/tools/verify_perspective_browser.py` 验证真实网页四点、测试图下载与矩阵自动复用。基准为 `upper/tools/profile_heading_observer.py`，记录保存在 `build/host-vision/heading-observer`。

S3维持原极性+1、PID 5/0.02/0.1、yaw±100%、100ms周期、20ms分配和现有IMU滤波／手动优先／全停逻辑。新航向命令沿用已实现Wi-Fi `heading_target` 与LoRa代码26；本轮仅修改PC端，不再生成不同固件。已有 `artifacts/RobotFish-ESP32S3-2.7.0-heading-target.bin` 未自动烧录。

旧 `upper/tools/verify_perspective_control.py` 仍可离线检查此前LOS／速度环与生产C++角度控制的组合，水动力为假设模型；它不代表当前网页启用视觉控制，也不证明实鱼水中稳定性。
