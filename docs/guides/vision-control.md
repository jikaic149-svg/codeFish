# 画线自动循迹与视觉调试

当前上位机为 `workstation-36-steering-priority`，固件为 `2.7.7-steering-priority`。默认启动只观测；绘制路径后，明确点击“开始自动循迹 · Wi-Fi”才执行路线。生产入口仍为 `vision/src/observer_runtime.py`。准备阶段检查混合摆尾配方、1.5摆幅增益和转向偏置优先能力。

## 当前默认：只跟整鱼，不检测白头

`speed_feedback_source=body_center`。红色 P 是 YOLO 整鱼框中心，短暂漏框沿用原有光流跟踪。用 P 的米制坐标做短窗口拟合，速度大小同时用于路径规划和推进速度闭环。这个对地速度包含侧漂，不是沿鱼头方向的前进速度。启动和运行都不需要白头，采样中的 `head_speed_state` 和 `head_point_source` 均为 `DISABLED`。启动前仍需标定场地、人工对齐一次 IMU 航向并画好路径；鱼体定位丢失或 IMU 失效仍有停机保护。重启上位机视觉进程即可生效，不需要重刷鱼端。

## 可选试验：白头前进速度反馈（默认关闭）

`vision/configs/control.json` 的 `speed_feedback_source` 选 `white_head_forward`。绿色空心圈是本帧检出的白色头罩，红色 P 仍是路径投影、历史轨迹与横向回正的位置。两个点先各自变换到米制坐标，头罩的位移取在前后两帧平均鱼身方向上的分量，用 0.40 s 窗口拟合，至少需要 3 个样本且跨度达到 0.12 s。得到的非负前进速度同时供路径规划与推进速度 PID 使用；横漂速度仍由 P 估计，控制航向仍由标定后的 IMU 提供。原地转头、侧漂、倒游均不等于向前推进；此值也不是相对水流速度。

白头测速就绪后允许人工启动，不要求点击时恰好看见白头。检测器接受暖白或中性白头罩；几何识别失败时，在鱼框平移补偿后的局部用头罩模板匹配当前图像，要求相似纹理与浅色中心。`head_point_source=CAP/PATCH/MISSING` 区分几何检出、图像匹配和未检出。鱼体仍在、白头短暂漏检或跳点时，`head_speed_state=HELD` 最多沿用上次可信前速 250 ms；`speed_sample_time` 保留真实采样时刻，不更新速度积分，匹配与保持不是一回事。超过窗口就暂停推进，再持续缺样超过原 250 ms 暂停期限则退出，不会自行重启；鱼体丢失、换鱼、IMU 和人工停止保护不变。只需重启上位机视觉进程，不涉及 ESP32 烧录。

可用 `tools/replay_head_feedback.py` 离线重复整段测速；需提供录像、四个池角像素以及池宽高。CSV 中 `shadow_power_pct` 是固定目标下原速度环本来会给出的推进量，不发到设备，不是闭环水动力结果。

头罩前后翻转、头到框中心的距离突变、去掉转头分量后仍过大的位移，均不进入测速。0.40 s 拟合对离群点降权，再按实际帧间隔做 90 ms 时间常数的低通。用 `python tools/review_head_feedback.py 采样.csv` 可生成 `*-review.csv` 和速度图。只在同一段跟踪、前后两个可信实测帧相隔不超过 250 ms 时，线性插值补绘中间的鱼头像素位置和速度。`review_state=INTERPOLATED` 不计作实测；滤波启动、长缺口或身份切换不补。所有原始列保留，补绘数据不进控制。

## 当前上位机：不同曲率与离轨回正（2026-11-18）

初始化仍按位置和鱼头选支；运行时只在上一投影的连续弧长区间内找最近点。区间随帧间隔和测速伸缩，允许小幅回退。明显跳点不进入控制用测速或引导，也不刷新上一有效位置的时间。原始检测中心仍可记录；采样 CSV 可用 `position_accepted`、`position_sample_time` 对照控制实际采用的帧。

平滑路段以投影处切向为基准，用局部有符号曲率提前转头；横向回正同时看偏差与实际横移速度。持续往外漂时多转，已经向路线靠拢时少转。目标航向限速仍为 35°/s。前速先按前方 37 cm 内的最大绝对曲率限速，再按**未限速**的目标角与鱼头的夹角平滑降速。严重失准保留曲率限速的 45% 作为速度目标，不是固定电机百分比；正常弯道目标可低于 0.04 m/s。相关参数见 `vision/configs/control.json` 的 `tangent_tracking`。曲率预算 0.17 rad/s 是仿真整定值，不是实鱼能力保证。

## 2.7.7：关节行程优先用于转向

2.7.6在摆幅加偏置超过关节行程时同比缩小两者，导致加大摆幅同时削弱转向。推进20%、满偏置时，前节请求半摆幅约16.77°、偏置24°；受±32°可用行程约束，原分配把偏置压到约18.84°。2.7.7先保留24°偏置，再以剩余8°作为半摆幅；直线继续采用1.5倍目标摆幅。该策略用于循迹与非baseline的混合标定，普通手动和旧基线保持原策略。机械行程、速率约束及原PID不变。

鱼端新增 `heading_bias_priority_supported`；`allocation` 的 `effective_tail_bias_deg` 与 `effective_tail_amplitude_deg` 表示关节行程分配后的前节名义偏置和半摆幅，位于最终角度速率限制之前，不是舵机实测反馈。终端、后台日志及观测CSV保存这些量；PC终端和CSV另保存路径进度 `along_m`、线段 `seg_index`，帮助检查交叉路径关联。193项针对性原生检查、原有分配/控制权回归、20项PC检查及编译通过；水中跟踪效果待实测，不能仅凭截图认定所有偏差都由这一冲突造成。

## 当前联合推进与加大摆幅

用户明确要求鱼尾既导向又摆动推进，替代此前32版“尾摆为0”的方案。当前尾驱动与双桨共同推进都由PC前向量给定；航向误差只移动尾摆中心，不追加35%尾推、不提高拍频。收油时两种推进一同归零。2.7.6将目标尾摆幅度乘1.5，正常低速拍频保持原调度；高需求时仍由原机械／速率约束限制实际输出。此增益用于循迹和非baseline的独立混合标定，静态对照因尾驱动为0仍不摆动，旧baseline保留原幅度。

前馈文件为 `measured_hybrid_dynamics_20261025.json`：旧混合直行尾摆+双桨10+10／15+15／20+20对应末2秒速度0.05734／0.14829／0.23488m/s，其中后两档未确认稳态。数据的摆幅增益为1，新运行增益为1.5，故只作初值参考，由原速度反馈纠偏。新增9段攻角实验全部为静态尾角，左转共同推进10%、右转20%；其中左-80%偏置拟合半径约0.378m，不能直接当作新摆尾配方的半径表。

16:53导出日志显示约73秒有效循迹没有永久退出，最终arrived；配方为hybrid_gait_tail_bias，尾驱动中位约11.44%，共同推进约11%，差动为0。该日志来自加大摆幅前。新固件编译和161项原生分配检查、20项PC检查及双测试配方阶跃不改推进的检查通过，未烧录或实鱼验证。

## 操作流程

1. 手动升级当前 `2.7.7-steering-priority` 应用 BIN（现有产物为 `build/firmware/robotfish.bin`；历史 `artifacts/` 已按用户要求清理），重新打开 `upper/start.cmd`，连接机器鱼Wi-Fi。程序不会自动切换电脑网络。
2. 在自动检测列表选择实时相机。场地固定3×1.6米，高度2.67米仅作为场景信息；同一相机、同一分辨率的已有四角自动复用，首次使用或相机移动后才重新选四角。
3. 在完整全局画面框选机器鱼，再选择所需视角并点击鱼头，建立视觉／IMU共同零位。鱼头标定冻结并保留当前原图或透视图，不再自动返回全局画面；透视坐标按同一矩阵反算原图。没有新鲜Wi-Fi IMU回传时先完成连接，再重新标定鱼头。
4. 从鱼附近沿期望行进方向拖动画线，填写目标速度。已删除0.36m/s输入上限，接受有限非负值；硬件实际能达到的速度另计。
5. 点击“开始自动循迹 · Wi-Fi”。程序先全停并关闭本机LoRa发送端，再连接Wi-Fi控制、同步零位，等待鱼端原有约3秒LoRa健康窗口释放后准备混合模式。其他LoRa发送器仍占用主控时不会启动。
6. PC只保留最新控制目标，最高10Hz通过Wi-Fi提交；100ms周期包含HTTP耗时，慢请求完成后发最新目标，不积压补发。转向误差交给S3角度环执行，推进量由PC视觉速度闭环计算。LoRa不会成为自动循迹的替代输出。
7. 数据页“循迹调试终端”分别输出PC与FISH，包含位置、视觉角、速度、LOS目标、误差、控制往返、鱼端PID分项和执行器指令，可暂停、筛选及导出TXT，最多1000行。
8. “停止自动循迹”和操控页全停用于停鱼；人工运动输入会撤销旧视觉任务。退出视觉、重新标定／选鱼／画线会退出自动控制。关闭预览和停止CSV采样仍允许自动循迹继续。

现有鱼端运动目标保持策略没有自动超时。完全失联时PC会停止更新并尝试发送全停，无法保证全停到达鱼端；状态未确认时明确显示未确认，不假装已停。此行为沿用原策略，本轮没有擅自增加鱼端保护或自动重启。

## 坐标、角度与透视

场地原点在左上，x向右、y向下；世界航向逆时针／左转为正。S3 的 `body_yaw_deg` 是安装映射后的局部顺时针航向，不代表地理北。

四角建立像素到米制的 H。机器鱼统一用整鱼 YOLO 检测框中心点 P 表示位置，短时漏检由原有光流更新同一点；轨迹、横移速度、转弯拟合、LOS 预览、网页与 CSV 的位置共用经 H 换算的 P。推进的标量速度由 `speed_feedback_source` 单独选择。暗色身体像素单独经 H 换算后拟合角度，不能直接把原图斜率当作实际角度。独立视觉角度来自 YOLO 鱼框内暗色身体轮廓的加权主轴，厚身体区域权重大于细尾，手动点头只解决前后180°歧义。它不使用 IMU 或位移方向，属于身体主轴观测，并非训练得到的头部关键点真值。遮挡、轮廓不清、轴不明确、身份变化或长时间失去视觉连续性时，角度无效；不以 IMU 填补视觉角度。

画面默认以红色 P 点显示位置，调试叠加仍可打开检测框与特征点。独立视觉角度继续采样和记录，不在画面上绘制。状态 position 提供 x_m/y_m、x_px/y_px、valid、track_id、sample_time 和 source=YOLO_BOX_CENTRE。valid 表示米制位置可用，需要场地标定及现有新鲜图像条件；尚未标定时仍提供像素点。sample_time 在实时相机中为接收时间减配置延迟，在回放中为视频时间。该点是检测框中心，不是物理重心。

标定图像中的视觉世界轴为 `psi0`，对应 IMU 为 `yaw0_cw`：

```text
visual_relative_left = wrap(visual_world_axis - psi0)
imu_relative_left    = wrap(yaw0_cw - body_yaw_cw)
manual_target_cw     = wrap(yaw0_cw - requested_relative_left)
visual_error        = wrap(target_relative_left - visual_relative_left)
```

目标只转换一次到 S3 局部航向。IMU 转角不经过 H。可选原图预览中绿色 IMU 箭头为对齐后的 IMU 方向，TARGET 箭头为鱼端回读的目标航向；二者的世界起点／终点统一经逆H投回原图。路径上的橙色圆圈是前视点，不代表鱼端已收到目标。

观测模式下，场地重标定更新观测几何、清空视觉零位并要求重新点头；自动循迹期间重标定先退出循迹并请求全停。每段 CSV 保存场地／鱼头标定ID，JSON保存对应矩阵、尺寸、源与零位快照，重标定前后的数据不能混用角度零位。设备 uptime 回退使 IMU 控制参考失效，正常32位回绕保留参考。

H按固定相机、近似同一观测平面建立，不补偿水深、折射、镜头畸变和相机移动；换相机位置后重新标定。

## 时间与采样

相机接收时间减去 `vision/configs/control.json` 的 `camera_latency_s`（默认沿用0.30s）作为估计采样时间，**不是硬件曝光时间**。IMU保存最多128份有效历史，按短圆弧插值，超过原0.35s对齐窗口时标无效。实际相机延迟需实验测定；配置误差和IMU滤波滞后仍会影响快速转动对比。

自动控制使用距当前时刻不超过0.35s的最新有效IMU及已标定零位；独立视觉测量仍使用图像时刻的历史IMU配对。单帧历史配对缺失不再直接终止持续控制，当前IMU过期、位置失效或设备重启造成零位失效仍会退出并记录原因。

角度按传感器样本时间插值；目标、控制零位和执行器命令按遥测快照时间保持阶梯值，不从未来快照取命令。CSV保留相机接收／估计采样时间、视频时间、IMU时间、插值跨度、原生遥测时间与设备uptime，以便后续检查时间误差。没有同一鱼头标定ID和有效时间配对时，不计算视觉与 IMU／目标的比较误差。

每个实际处理的相机帧最多写一行，包含独立视觉世界／相对角度、X/Y轨迹、有效性／原因、主轴质量、YOLO置信度及跟踪来源、IMU、目标、PID误差和P/I/D、推进、尾舵／双桨命令、LoRa序号与阶段耗时。执行器列是驱动命令，不是实际位置或推力反馈；缺失值留空。插值不提高 IMU 的真实采样频率。

CSV每秒刷新，停止／正常退出后收尾保存；保存错误和异常退出不标为完整成功。导出仅允许本轮输出目录内的已停止完整文件。元数据同时保留模型路径／SHA256、相机时延设定和各次标定。

下述吞吐数字是前一轮3fps显示配置的离线基准；当前15fps透视显示和用户主动录像会增加渲染／编码开销，网页实时耗时为准。

PC总算力不能直接等同于单路视觉速度：解码、缩放／CPU到GPU传输、框结果回读、跟踪、显示和网络有串行部分，小模型单帧GPU工作后还要等待这些阶段。CPU总利用率低也不表示关键线程没有瓶颈。先看阶段耗时和图像年龄，再决定是否降低检测尺寸或改变模型；本轮未做模型转换或量化。

### 实测表契约

在同一驱动模式、尾／桨配方、载荷、供电和观测平面下采样。只接收 HYBRID 数据；直线和弯道两侧分开验证，不自动把单桨或纯鱼尾数据用于混合循迹。source_segments 是可追溯的原始测段目录或ID。下面是不可直接启用的空模板；代码没有填入任何合成测量值：

```json
{
  "schema": 1,
  "profile_id": "填写本次混合驱动实测批次",
  "drive_mode": "HYBRID",
  "coast_method": "zero_forward_keep_steering",
  "source_segments": ["填写原始测段ID"],
  "samples": []
}
```

每一行 samples 必须包含有限正数：speed_mps（m/s）、coast_distance_m（m）、left_radius_m（m）、right_radius_m（m）。至少两行，按速度递增排列，滑行距离也须严格递增；测量有噪声时先人工核对保守包络，代码不会擅自把异常数据改成有效数据。表格须覆盖最低紧弯速度及所用巡航速度。半径没有可靠拟合结果的测段不能填0。

coast_distance_m 表示将前向驱动归零、保留相应转向配置后到稳定的位移；应保留发出／回读／相机时间戳以核查延迟。急停、反推或不同混合配方得到的距离不能混入。D(v)-D(v_target) 用于估算速度下降距离，假定本批次减速规律一致；它仍需实测检验，并不构成物理制动保证。数据缺失、错误、模式不符或未覆盖巡航速度时，新规划保持未激活并上报原因，不外推不存在的标定。

### 后续启用后的路径和速度

准备路径时先按2cm容差去除细碎毛刺，再根据左右实测半径生成相切圆角，保留首尾点，最后按3cm重采样。gentle_speed_mps=0.07、tight_speed_mps=0.045 为待调起点；对应的可用速度和半径取实测表中不高于该档位的最近测量行。max_rounding_offset_m=0.15 限制每个角点到圆弧的偏移，空间不足、近180°折返或圆角后仍超出能力时拒绝该路线。圆角离散预留2%用于数值误差，不代表实测安全余量。

规划按 D(v_i) ≤ 路段长度 + D(v_(i+1)) 从终点向前计算速度上限，使前方弯道的减速提前作用于直线段。该上限只降低现有速度目标，不发反推、不改PID参数。超过实测速度范围的运行中设定会明确拒绝。启用后紫线显示实际圆角路线，原始画线仍保留在 path_pixels，planned_path_m 提供执行路径。

执行器数据沿用图像时间之前的遥测快照，避免借用未来命令；旧固件缺失字段留空。目标ID、场地标定变化、超过0.35秒的采样间断会清空一秒复核窗口。开关关闭时扩展CSV列留空，不增加验证用位置历史。

后续有真实数据时：先录入并核验表格，单独开启日志复核，再由用户显式启用曲线规划和固件选项。当前默认关闭状态不需要操作机器鱼。
